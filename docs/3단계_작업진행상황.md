# 3단계 작업 진행 상황

## 2026-11-20 재개 시 확인한 상태

- 브랜치: `database`. 1·2단계와 3단계의 미커밋 변경을 보존했다. 초기화·커밋·push·deploy를 하지 않았다.
- 이미 작성된 부분: Dexie v2 `canvasContents` 스키마, PNG Repository, Canvas 저장/복원 hook, 브라우저 통합 검사 초안.
- 이어서 처리한 부분: 실제 DrawingSpace 연결, 데이터 Router의 이동 차단, 인증 서비스의 저장 후 로그아웃, Canvas 오류 처리, 통합 검사의 실행 환경 및 검사 좌표 보완.
- 기존 CSS, 레이어 목록 코드, Firebase 초기화 파일을 이번 재개 작업에서 새로 만들거나 개편하지 않았다.

## 재개 후 검증 중간 기록

- 최초 검사 실패 원인: 테스트 브라우저의 loopback 접근 권한 거부. Firebase 운영 서버로 전환하지 않았다.
- Playwright의 격리된 테스트 출처에만 `local-network-access` 권한을 부여하여 해결했다.
- 색상 검사에서는 둥근 모서리 바깥을 클릭하던 테스트 좌표를 색상 사각형 내부로 수정했다. 기존 색상 선택 UI는 변경하지 않았다.
- PNG 검사는 실제 PNG를 디코딩한 전체 RGBA 바이트의 SHA-256과 화면 Canvas를 비교한다.
- 기존 사용자의 DB와 Emulator 계정을 삭제하지 않는다. 별도 브라우저 컨텍스트와 실행별 임시 계정을 사용한다.

아래 완료 기록이 없다면, `scripts/test-canvas-persistence.mjs`와 `scripts/test-artwork-metadata.mjs`의 최종 실행 결과 확인, 빌드·lint 재실행, `docs/Canvas_PNG_저장복원_연동검증.md`의 미검증 표 갱신부터 이어서 진행한다.

## 범위와 보장 한계

- 단일 Canvas PNG의 로컬 저장만 구현한다. 레이어별 PNG, Storage, 서버 동기화, 편집 세션, 수정 이력, 강제 복구는 후속 범위다.
- 정상 앱 이동과 인증 서비스 로그아웃은 저장을 기다린다. 강제 종료·다른 탭에서의 로그아웃·SDK 직접 호출은 사전 저장을 보장하지 않는다.
- UID 구분은 앱 수준의 분리다. 로컬 DB 자체가 서버 보안 경계는 아니다.
- 작품 메타데이터 각 변 1~8192는 유지하고, 렌더러의 메모리 보호 상한은 총 16,777,216픽셀이다.

## 2026-11-20 완료 기록

- 단일 Canvas PNG Blob의 자동 저장·재열기·F5 복원을 완료했다. 3단계 범위 내 미완료 구현은 없다.
- PNG 브라우저 통합 검사: **27/27 통과**. 원본·복원본 RGBA 일치, 지우개, 저장 중 추가 획, 오류 재시도, UID 구분, v1→v2 보존, 내부 이동·뒤로가기·로그아웃 저장을 확인했다.
- 기존 작품 메타데이터 회귀 검사: **24/24 통과**. 가입·로그인·프로필, 작품 CRUD·검색·정렬·UID 분리 유지.
- `npm.cmd run build`: 성공. JS 청크 크기 경고는 남아 있다.
- `npm.cmd run lint`: 종료 코드 0. 오류 0개, 기존 UI 경고 3개.
- 두 최종 검사 실행 모두 실행별 Emulator 계정·프로필 정리 성공. 기존 브라우저 IndexedDB 데이터 삭제 없음.
- 자동 검사 중 browser back 검사에서는 POP 직후 주소창만 먼저 바뀌는 특성을 반영하여 실제 목록 UI 마운트를 기다리도록 수정했다. 저장 구현을 생략하거나 픽셀 비교 기준을 낮추지 않았다.
- 상세 변경 파일·실행 방법·검증 결과·미검증 항목은 [Canvas PNG 연동검증](./Canvas_PNG_저장복원_연동검증.md)에 기록했다.
- 실행 결과 JSON은 `docs/test-results/2026-11-20-canvas-persistence.json`, `docs/test-results/2026-11-20-artwork-metadata.json`에 보관한다.
