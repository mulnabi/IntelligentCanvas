# IntelligentCanvas 7단계 DB 안정화

## 7-A 서버 작품 소프트 삭제

- 소유자 Callable은 예상 버전과 편집 세션의 반납을 확인하고, 서버 문서에 삭제 상태·시각·요청 ID를 기록하며 버전을 한 번 올린다. 같은 요청과 원래 버전으로 다시 호출하면 같은 결과를 반환한다.
- 요청 브라우저의 미동기화 대기열과 복구 초안이 있으면 삭제를 차단한다. 다른 브라우저의 IndexedDB는 서버가 읽을 수 없으므로 해당 브라우저가 삭제를 확인할 때 로컬 원본을 보존한다.
- 목록을 열거나 다시 연결하거나 창에 돌아오면 브라우저가 알고 있던 작품의 삭제 여부를 확인한다. 삭제 표식이 확인된 작품은 활성 목록에서 빠지고, 캐시가 있으면 읽기 전용 로컬 보존본에서 확인할 수 있다.
- Firestore 작품에 `state: deleted`, `deletedAt`, 증가한 `serverVersion`, `deletion.requestId`를 기록한다. Dexie v5의 기존 레코드에 `serverDeletedVersion`을 남긴다. 삭제된 작품의 이전 저장·세션 획득과 재등록은 서버에서 거부된다. 확정 레이어·Storage 원본·복구 초안과 대기열을 보존한다.
- 기존 로컬 작품 삭제도 **작품 관리 → 삭제**를 사용한다. 서버 등록 작품은 동기화와 정상 반납 후 같은 메뉴에서 삭제한다. 삭제 확인은 목록 진입·명시적 새로고침·브라우저 초점 또는 온라인 복귀를 기준으로 한다.

## 7-B 대용량 PNG 보존과 재시도

- 업로드 전에 레이어별 8 MiB를 확인하고 문제가 있는 레이어의 이름을 표시한다. 용량 실패는 자동 재시도를 중단한다.
- 사용자가 그림판에서 레이어를 수정해 새 로컬 버전을 저장한 후 명시적으로 재시도할 수 있다. 서버의 현재 세션·버전과 진행 중 요청이 없는지 확인한다. 실패한 동결 요청은 PNG Blob째 복구 초안으로 보존하고, 새 버전의 대기열과 함께 Dexie 트랜잭션으로 확정한다.
- 8 MiB 정책과 Dexie v5를 유지한다. 기존 버전에서 이 메시지로 실패한 요청도 재시도 대상에 해당할 수 있다. 레이어를 그대로 두고 재시도하면 안내를 표시하며 기존 요청을 유지한다. 용량이 충분하지 않아 초안 기록이 실패하면 트랜잭션 전체가 취소된다.

## 7-C 서버 목록 페이지

- 인증된 UID의 활성·서버 확정 작품만 한 번에 20개씩 가져온다. 같은 값에서도 다음 페이지를 결정할 수 있게 정렬 값과 작품 ID를 커서로 사용한다. 동일 기기에서 받은 페이지와 로컬 카드는 작품 ID로 합친다. 정렬 변경과 새로고침에서는 첫 페이지부터 조회한다. [Firestore 쿼리 커서](https://firebase.google.com/docs/firestore/query-data/query-cursors)
- 제목 부분 검색은 로컬 작품과 현재 불러온 서버 페이지에 적용된다. 전체 서버 작품의 한글 부분 검색과 전체 이름순의 로캘 순서는 후속 범위다. 화면에서 이미 불러온 제목은 기존 한국어 비교로 정렬된다.
- 오프라인 기기는 다시 연결될 때 이미 캐시된 작품의 삭제 여부를 대조한다. 서버에서 받은 삭제 표식은 새로고침 이후에도 유지된다.

## 직접 확인

1. 로컬 Emulator와 개발 서버를 실행하고 두 브라우저 프로필에서 같은 테스트 계정으로 로그인한다. 실행 명령과 포트는 [6단계 문서](./6단계_DB_최종검증.md#직접-확인하는-방법)를 참고한다.
2. A의 테스트 작품을 서버에 동기화하고 **서버 저장 후 편집 종료**를 누른다. **작품 목록 → 작품 관리(⋮) → 삭제**에서 확인한다. B에서 **서버 작품 보기**로 갱신한다. 카드는 활성 목록에서 빠지며 이미 저장된 캐시는 **서버에서 삭제된 작품의 로컬 보존본**에서 확인할 수 있다.
3. 용량 초과 안내가 표시된 테스트 작품은 해당 레이어를 직접 수정하고 로컬 저장을 확인한다. **레이어 수정 후 동기화 다시 시도**를 누른 뒤 **서버 동기화 완료**와 **이 브라우저의 복구 초안**을 확인한다.
4. 서버 작품을 21개 이상 생성한 테스트 계정으로 **서버 작품 보기 → 서버 작품 더 보기**를 누른다. 제목 검색과 정렬을 확인하고 다른 UID로 바꿔 해당 계정의 작품만 보이는지 확인한다.

## 운영 전 남은 확인

- 운영 프로젝트에서 정렬별 복합 인덱스 3개의 준비 상태를 확인해야 한다. Emulator 검증과 별도로 실제 프로젝트 인덱스 및 운영 환경분리·권한 검증이 필요하다.
- 삭제 원본의 보존 기간과 영구 삭제 절차는 별도 정책으로 정한다. 운영의 레이어 제한을 바꿀 경우 클라이언트·서버 상한을 함께 검토하고 모바일 메모리, 요청 크기, 비용을 측정한다.
- 실제 모바일 데이터 전환, 장시간 오프라인과 브라우저 저장 공간 고갈은 이번 브라우저 프로필 검사 범위 밖이다.
